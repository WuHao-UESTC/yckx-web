# 功能基线

本文档记录工程重构前必须保留的功能和行为。除非在变更记录中明确说明，否则重构后的页面、接口和数据迁移不得删除这些能力。

## 公共站点

| 领域     | 路由              | 必须保留的能力                                                                             |
| -------- | ----------------- | ------------------------------------------------------------------------------------------ |
| 首页     | `/`               | 品牌入口、精选文章、文章日历、可拖拽知识分类图谱与批次文章预览、事件、照片、便签和成员预览 |
| 知识库   | `/knowledge-base` | 分类浏览、分类文章列表、文章详情、标签、附件、目录、上下篇和评论                           |
| 竞赛     | `/competition`    | 竞赛分类、文章列表和文章详情                                                               |
| 大事记   | `/events`         | 年份时间线、专栏入口、事件详情和专栏详情                                                   |
| 科协日常 | `/routine`        | 照片墙、图片查看、便签发布和删除                                                           |
| 成员     | `/friends`        | 成员列表、成员主页和成员文章                                                               |
| 搜索     | `/search`         | 标题和正文搜索、搜索结果高亮                                                               |
| 聚合     | `/tags/[tag]`     | 按标签浏览已发布文章                                                                       |

### 首页 80m 知识潮汐

- 分类图谱必须由分类间的稳定稀疏连接组成，不得依赖单一中心节点；全部分类保持连通，每个节点最多四条连接。
- 水母节点可以拖拽，拖拽期间与其直接相连的实线和相邻节点必须高亮，连接线必须实时跟随位置变化。
- 空闲节点保持缓慢、不规则的自由移动；悬停或聚焦只让当前节点减速，选中节点固定位置但保留水母律动和呼吸微光。
- 图谱不得显示用于框定活动范围的边框、内圈或容器卡片；安全边界仍需阻止节点离开可操作区域。
- 点击分类只进行金色选中并打开附近文章列表，不直接导航；文章列表不得遮挡选中节点，每批最多五篇并保留“换一批”和“进入分类”。

### 首页 300m 竞赛航线

- 声纳区域最多展示七个互不重叠、位置稳定的竞赛分类，点击分类只切换探测模式，不直接导航。
- 声纳扫描必须包含可辨认的拖尾；扫描经过目标时显示短暂金色边缘，选中目标保持金色状态。
- 未选中分类时只展示已发布的精选竞赛文章；选中后只展示该分类下的已发布文章。
- 文章使用七个北斗星位展示，每批最多七篇，保留稳定游标“换一批”；分类模式必须提供“进入该竞赛”，默认模式提供竞赛中心入口。
- 加载、错误、空状态和文章批次变化不得撑高 300m 章节或改变首页章节坐标。

## 数据与集成

- PostgreSQL 数据必须原地兼容或通过可回滚迁移升级。
- 上传文件必须保留，公开附件只能暴露安全元数据，不得暴露 NAS 绝对路径。
- 已发布文章的现有 URL 必须保持可访问。
- Giscus 评论、Markdown、KaTeX、Mermaid、Markmap、代码高亮和 PDF 内容能力必须保留。
- NAS 的 standalone 部署方式必须保留。

## 权限基线

- 未登录用户只能读取已发布内容和公开资料。
- 普通成员只能修改自己的文章、资料、文件和便签。
- 管理员可以管理全站用户、内容、分类、照片、邀请码和站点配置。
- 页面可见性不是安全边界；Route Handler 和 Server Action 必须独立鉴权、授权和校验输入。

## 重构验收

每个阶段至少通过以下检查：

1. `pnpm format:check`
2. `pnpm lint`
3. `pnpm typecheck`
4. `pnpm test`
5. 对本阶段涉及的路由执行手工或端到端回归
