# 安全边界

## 已修复风险

- 文章列表接口可通过 `status=all` 绕过已发布限制。
- 单篇文章接口可读取未发布文章，并返回附件的 NAS 绝对路径。
- 文件下载接口没有区分公开附件和用户私有文件。
- Server Action 依赖页面布局鉴权，没有在操作内部统一复核权限。
- 种子脚本包含固定管理员密码和固定邀请码。
- 多个 JSON 和 FormData 入口使用手写、非统一校验。

## 当前安全边界

- 公共读取只能返回已发布内容。
- 草稿和归档内容仅作者或管理员可读。
- 数据库用户记录是安全写操作的最终角色来源，JWT 只用于定位用户。
- 所有写入口使用共享 Schema 校验。
- 大事记新增、修改和删除只允许管理员执行，Server Action 内部必须重新读取数据库用户角色。
- 公共 DTO 永远不包含 `passwordHash`、`storedPath` 和其他内部字段。
- 登录邮箱 `User.email` 永不公开；公开联系邮箱、QQ 和微信只有用户主动填写到 `Profile` 后才出现在个人主页，并默认遮挡，点击显示时仅在浏览器端尝试复制。
- `Profile.website` 允许自由文本保存，公共渲染只接受相对路径和 `http/https` 协议，拒绝 `javascript:`、`data:` 等危险协议。
- `/friends` 和首页成员流包含管理员属于预期公开行为；管理员身份标签不改变后台权限检查。
- 种子管理员密码和邀请码必须由环境变量提供，禁止默认生产凭据。
- 上传文件依据受支持 MIME、文件签名和聚合配额校验，存储路径必须位于 `UPLOAD_DIR`。
- 附件绑定必须重新读取文件记录，校验上传者、文章所有权和已有绑定，不能信任客户端文件 ID 列表。
- 匿名下载只允许绑定到已发布文章的附件；匿名内联预览只允许已发布文章所绑定的图片/PDF或公开日常照片。草稿、归档文章和未绑定文件的下载与预览只允许上传者、文章作者或管理员读取。
- 分类和专栏创建需要登录，领域服务必须阻止技术、新闻和日常之间的非法分类或专栏组合。
- 技术专栏必须重新读取所属分类；文章多专栏写入必须验证所有专栏存在、启用且属于文章当前分类。
- 新闻多专栏写入必须重新读取全部专栏，验证其类型为 `NEWS`、状态可用，并拒绝旧 `EVENT` 大事记文章建立新闻专栏关系。
- 日常多专栏写入必须重新读取全部专栏，验证其类型为 `DAILY`、状态可用，并拒绝技术文章或新闻建立日常专栏关系。
- 公共照片搜索必须在服务端固定 `Photo.kind = WALL` 和 `Photo.isVisible = true`；描述和日期参数只能缩小公开普通照片集合，不能读取隐藏照片或顶部合照。
- 分类和专栏重命名必须重新读取创建者，普通成员只能修改自己创建的项目，管理员可以修改全部；客户端不能提交或改写 slug。
- 成员只能创建普通照片墙记录，并只能修改和删除自己的照片；`Photo(kind = GROUP)` 只允许管理员创建且必须填写年份，管理员可以排序、隐藏、恢复和删除全部照片。
- 批量删除必须在服务端重新解析所有资源 ID，限制每次数量，并与单项删除共用角色和保护规则。
- 管理员不能删除当前登录账号，也不能删除系统中最后一名管理员。
- 头像只允许 JPEG、PNG 和 WebP，上传时同时校验 MIME、文件签名、文件大小和解码结果；客户端不能直接写入头像路径。
- 注册邀请码在 Serializable 事务内消费，并对并发冲突进行有限重试。
- 游客与科协人员注册均先发送一次性邮箱验证码，验证码只保存哈希、10 分钟过期、单次消费并限制尝试次数；科协人员邀请码只在验证码验证成功的最终事务内消费。
- 登录只允许 `emailVerifiedAt` 已设置的账号；找回密码使用独立的重置验证码，页面文案不提示邮箱是否存在，挑战详情只用于已创建的重置流程。
- 游客角色只能调用评论和订阅接口，所有内部内容写接口使用成员/管理员鉴权；游客评论直接发布，管理员通过后台手动删除。
- 站内评论仅允许已登录用户针对已发布文章写入，服务端限制评论长度、回复对象和短时间重复发布。
- 邮件通知采用 Outbox，发布事务只写入待发送记录；处理接口使用独立密钥保护并支持失败重试和去重。
- 生产环境的通用错误响应和日志不输出完整异常对象、数据库信息或文件系统路径。

## 仍需在部署层完成

- 在反向代理为登录、注册、上传和写接口配置速率限制与请求体上限。
- 为邮箱验证码请求、密码重置、评论和邮件处理接口配置独立速率限制；SMTP 凭据和邮件 worker 密钥只存在 NAS 环境变量或密钥管理中。
- 为成员分类、专栏、留言和照片写接口配置独立速率限制，避免全局内容组织被批量滥用。
- 为生产域名配置 HTTPS、HSTS 和适合站内评论/图片来源的 Content-Security-Policy。
- 确认 NAS 文件权限只授予运行应用的专用账户，并配置备份保留与恢复演练。
- 根据实际威胁模型决定是否增加恶意文件扫描、审计日志和告警。

## 生产操作要求

- 数据迁移前分别备份 PostgreSQL 和上传目录。
- 备份必须验证可读取，数据库备份必须至少执行一次恢复演练。
- 部署使用最小权限数据库账户和专用上传目录。
- `AUTH_SECRET`、数据库密码和种子凭据只存在于 NAS 环境变量或密钥管理中。
- 不在日志、Git、文档和 API 响应中输出凭据。
- 生产数据库只运行已审核迁移，不运行 `db push`、`migrate dev` 或 `migrate reset`。

## 待确认的生产信息

- NAS SSH 用户、端口和部署目录。
- Docker Compose 项目名称、PostgreSQL 服务名和卷名。
- 当前生产数据库是否执行过旧种子脚本。
- 上传目录的实际位置和备份保留策略。
