# 安全边界

## 已修复风险

- 文章列表接口可通过 `status=all` 绕过已发布限制。
- 单篇文章接口可读取未发布文章，并返回附件的 NAS 绝对路径。
- 文件下载接口没有区分公开附件和用户私有文件。
- Server Action 依赖页面布局鉴权，没有在操作内部统一复核权限。
- 种子脚本包含固定管理员密码和固定邀请码。
- 多个 JSON 和 FormData 入口使用手写、非统一校验。

## 当前安全边界

- 公共读取只能返回已发布内容。
- 草稿和归档内容仅作者或管理员可读。
- 数据库用户记录是安全写操作的最终角色来源，JWT 只用于定位用户。
- 所有写入口使用共享 Schema 校验。
- 公共 DTO 永远不包含 `passwordHash`、`storedPath` 和其他内部字段。
- 种子管理员密码和邀请码必须由环境变量提供，禁止默认生产凭据。
- 上传文件依据受支持 MIME、文件签名和聚合配额校验，存储路径必须位于 `UPLOAD_DIR`。
- 注册邀请码在 Serializable 事务内消费，并对并发冲突进行有限重试。
- 生产环境的通用错误响应和日志不输出完整异常对象、数据库信息或文件系统路径。

## 仍需在部署层完成

- 在反向代理为登录、注册、上传和写接口配置速率限制与请求体上限。
- 为生产域名配置 HTTPS、HSTS 和适合 Giscus/图片来源的 Content-Security-Policy。
- 确认 NAS 文件权限只授予运行应用的专用账户，并配置备份保留与恢复演练。
- 根据实际威胁模型决定是否增加恶意文件扫描、审计日志和告警。

## 生产操作要求

- 数据迁移前分别备份 PostgreSQL 和上传目录。
- 备份必须验证可读取，数据库备份必须至少执行一次恢复演练。
- 部署使用最小权限数据库账户和专用上传目录。
- `AUTH_SECRET`、数据库密码和种子凭据只存在于 NAS 环境变量或密钥管理中。
- 不在日志、Git、文档和 API 响应中输出凭据。
- 生产数据库只运行已审核迁移，不运行 `db push`、`migrate dev` 或 `migrate reset`。

## 待确认的生产信息

- NAS SSH 用户、端口和部署目录。
- Docker Compose 项目名称、PostgreSQL 服务名和卷名。
- 当前生产数据库是否执行过旧种子脚本。
- 上传目录的实际位置和备份保留策略。
