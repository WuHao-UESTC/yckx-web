# 内容领域重构设计草案

## 目标

将成员工作台中笼统的“写文章”拆分为三条稳定的内容航道：技术文章、新闻和日常。重构继续使用模块化单体与统一文章主表，不复制搜索、标签、评论、附件、草稿、发布和阅读统计能力。

本次变更同时覆盖 PostgreSQL 数据模型、领域服务、Route Handler、成员工作台、管理后台和公共页面。现有公开 URL、已上传文件和历史内容必须保持可访问。

## 内容模型

| 内容           | 持久化模型               | 组织方式                                          |
| -------------- | ------------------------ | ------------------------------------------------- |
| 知识库文章     | `Post(kind = TECHNICAL)` | `Category(type = KNOWLEDGE)` + 可选多个技术专栏   |
| 竞赛文章       | `Post(kind = TECHNICAL)` | `Category(type = COMPETITION)` + 可选多个技术专栏 |
| 普通新闻       | `Post(kind = NEWS)`      | 可不选择专栏                                      |
| 新闻专栏       | `Post(kind = NEWS)`      | 可选多个 `Column(type = NEWS)`                    |
| 留言           | `StickyNote`             | 独立短内容流                                      |
| 照片与感悟     | `Photo` + `File`         | NAS 图片文件与文字描述                            |
| 日常文章       | `Post(kind = DAILY)`     | 可独立收录，也可加入多个 `Column(type = DAILY)`   |
| 首页大事记坐标 | `Milestone`              | 管理员维护的独立时间点                            |

旧 `EVENT` 文章继续通过原有 `/archive/events/[slug]` 访问，但不再作为成员的新建入口。旧新闻分类只承担历史兼容，新新闻由 `Post.kind` 和新闻专栏组织。

## 分类与专栏权限

- 所有已登录成员可以创建知识分类、竞赛类别、新闻专栏和日常专栏。
- 新建分类或专栏立即可用于写作，并记录创建者。
- 技术专栏必须归属于一个知识分类或竞赛类别；文章只能加入当前分类下的技术专栏，可以不加入或同时加入多个。
- 新闻专栏不归属于技术分类；普通新闻可以不加入或同时加入多个新闻专栏，旧 `EVENT` 大事记文章不得加入新闻专栏。
- 日常文章可以不加入或同时加入多个日常专栏，作者和管理员可以在文章管理中调整全部日常专栏关系。
- 分类与专栏创建者可以修改自己创建项目的显示名称，管理员可以修改全部项目；slug 在重命名后保持不变。
- 普通成员不删除全局分类或专栏，避免破坏其他成员文章。
- 管理员可以停用、恢复、排序和治理重复项。
- 停用项不出现在新建表单中，已有关联内容仍可读取和编辑。
- 服务端必须验证文章领域与分类、专栏类型的组合，不能信任客户端筛选结果。

## 发布流程

### 技术文章

成员选择知识库或竞赛分类，按需加入该分类下的一个或多个专栏，再填写标题、正文、标签和附件。发布时必须存在有效分类。更换分类时自动移出原分类下的专栏。

所有文章都保存可选的 Markdown 渲染风格。未选择或历史文章使用新版默认样式，另提供技术文档和论文阅读样式；样式只改变展示，不改变 Markdown 源文和目录结构。

### 新闻

普通新闻可以不选择专栏；竞赛获奖、活动报道等系列内容可以同时选择多个新闻专栏。旧事件文章保留原展示入口，但不参与新闻专栏关联。

### 日常

日常工作区提供留言、照片与感悟、日常文章三个并列入口。留言和照片使用轻量表单，日常文章复用完整 Markdown 编辑器。日常文章可以不选专栏，此时直接出现在日常文章列表中；选择一个或多个专栏后同时进入对应专栏目录。公共 `/routine` 的舱内留言区域只展示留言，不提供输入框，留言发布继续通过登录后的工作区完成。

## 管理删除

- 文章、用户、分类、专栏和邀请码均支持单项与批量永久删除，不进入回收站。
- 删除分类或专栏时保留文章，并将对应关联置空；删除文章时附件回到上传者的私有文件库。
- 删除用户时同步删除其文章、评论、留言、照片、邀请码、个人资料和文件记录，并在数据库提交后清理 NAS 文件。
- 当前登录管理员不能删除自己，也不能通过批量操作删除系统中最后一名管理员。

## 头像生命周期

- 个人资料不再接受头像 URL，只接受 JPEG、PNG 或 WebP 文件上传。
- 服务端校验文件签名，将图片裁剪为方形并统一转换为 WebP，再保存到 `UPLOAD_DIR`。
- `User.avatarFileId` 记录当前头像文件，`User.avatar` 保留可公开读取的站内预览路径以兼容现有展示查询。
- 替换或移除头像后删除旧文件记录和 NAS 实体；历史外部头像 URL 仅作读取兼容，不再提供填写入口。

## 附件生命周期

1. 上传文件先创建为成员私有文件。
2. 保存文章时提交附件 ID 列表。
3. 服务端在事务内验证上传者和绑定状态，再关联文章并保存顺序。
4. 解除关联或删除文章后，文件恢复为私有文件。
5. 只有已发布文章的附件允许匿名下载。
6. 草稿和归档文章附件只允许上传者、文章作者或管理员下载。
7. 公共 DTO 不返回 `storedPath`，下载响应不暴露 NAS 目录。

照片文件使用独立的内联预览响应。只有公开照片允许匿名读取，私有或隐藏照片仍执行所有者/管理员检查。

## 路由设计

- `/dashboard/editor`：内容航道选择。
- `/dashboard/editor/technical`：新建技术文章。
- `/dashboard/editor/news`：新建新闻。
- `/dashboard/editor/daily`：新建日常专栏文章。
- `/dashboard/editor/[id]`：按文章领域编辑已有内容。
- `/dashboard/routine`：留言和照片发布工作区。
- `/dashboard/taxonomies`：成员分类与专栏创建。
- `/knowledge-base/[category]/columns/[column]`：知识分类下的技术专栏目录。
- `/competition/[category]/columns/[column]`：竞赛类别下的技术专栏目录。
- `/archive`：按“Milestone 星链、新闻专栏、科协新闻”顺序展示；搜索与排序只作用于科协新闻。
- `/archive/columns/[slug]`：新闻专栏目录，支持范围搜索和拼音/日期排序。
- `/routine/entries/[slug]`：日常专栏文章详情。
- `/routine`：按“照片墙、日常专栏与文章、舱内留言”顺序展示；照片支持描述/日期检索，日常文章支持搜索和拼音/日期排序。
- `/routine/columns/[slug]`：日常专栏目录，支持范围搜索和拼音/日期排序。

现有知识库、竞赛、新闻、事件和文章编辑 URL 保持兼容。

## 视觉与交互

工作台继续使用 `1800m / 同行灯火` 的舱内科研日志视觉，管理后台继续使用 `4000m / 海底星图`。新增界面的核心识别元素是三条内容航道：技术使用生物光青，新闻使用档案铜金，日常使用舱灯暖绿。颜色只用于领域、焦点和状态，不制作营销式卡片或首页级动画。

编辑器保持高密度、稳定尺寸和可扫描布局。附件区使用文件行、上传图标、移除图标和明确状态；分类与专栏使用原生选择控件；所有异步操作提供禁用、成功和具体错误状态。

## 数据迁移

1. 新增 `PostKind`、`ColumnType` 和 `FilePurpose`。
2. 根据旧分类类型和旧 `PostType` 回填文章领域。
3. 所有现有专栏回填为新闻专栏。
4. 分类、专栏增加创建者和启用状态；历史记录创建者允许为空。
5. 文件增加用途和附件顺序；照片增加文件关联、公开状态和更新时间。
6. 保留旧照片 `imagePath`，新上传照片同时记录 `fileId`，避免移动或丢失历史图片。
7. 增加领域、专栏和文件关联索引。
8. 新增新闻文章与新闻专栏多对多关系，回填现有新闻 `columnId` 后清空新闻旧单选关系；该阶段暂时保留日常文章的旧单专栏关系。
9. 新增日常文章与日常专栏多对多关系，回填现有日常 `columnId` 后清空日常旧单选关系；`columnId` 仅保留为历史兼容字段。

生产环境只执行已审核迁移。迁移前必须同时备份 PostgreSQL 和 `UPLOAD_DIR`，完成迁移后重新生成 Prisma Client 并重启 NAS 开发进程。

## 验收范围

- 三类文章可以创建、保存草稿、编辑和发布。
- 技术文章可以加入同一分类下的多个专栏，并可由作者或管理员在文章管理中移入或移出。
- 普通新闻可以加入多个新闻专栏，并可由作者或管理员在文章管理中移入或移出；大事记文章被服务端拒绝。
- 日常文章可以加入多个日常专栏，并可由作者或管理员在文章管理中移入或移出。
- 知识库、竞赛、分类和技术专栏目录支持范围内搜索，并按中文拼音首字母或发表日期排序。
- Archive 首页和新闻专栏目录支持范围内搜索，并按中文拼音首字母或发表日期排序；Milestone 星链保持日期顺序。
- Routine 首页和日常专栏目录支持范围内文章搜索，并按中文拼音首字母或发表日期排序；照片墙支持描述关键词和上传日期范围搜索，每墙最多十张且按上传时间倒序。
- 默认、技术文档和论文阅读三种 Markdown 样式均保留代码、公式、表格、图表、PDF、目录和附件能力。
- 领域与分类、专栏的非法组合被服务端拒绝。
- 成员可以创建四类内容组织项，管理员可以停用和恢复。
- 附件可以上传、绑定、排序、解除关联并由匿名访客下载。
- 日常照片由成员上传并带有描述，管理员可以隐藏。
- 公共舱内留言只读，发布入口只存在于登录后的日常工作区。
- 旧知识、竞赛、新闻、事件 URL 和旧照片保持可访问。
- 搜索、标签、成员文章、首页新闻和公开统计继续只读取已发布内容。
- 格式化、Lint、Prisma 校验、类型检查和测试通过。
